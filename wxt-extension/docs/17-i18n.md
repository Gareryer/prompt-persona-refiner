# 17 - Internationalization (i18n) Architecture

> **Target Layer**: Multi-Language Localization Engine  
> **Tooling**: `@wxt-dev/i18n` / Chrome WebExtension `_locales`  
> **Supported Locales**: English (`en`), Spanish (`es`), Japanese (`ja`), Simplified Chinese (`zh_CN`), German (`de`)  
> **Classification**: Localization & Internationalization Specification

---

## 1. Overview & WXT i18n Architecture

Standard WebExtension localization requires querying raw message keys via `chrome.i18n.getMessage('key')`, which provides no compile-time type safety, no placeholder verification, and fails silently if a key is mistyped.

**Allie Persona & Prompt Refiner** leverages **WXT's type-safe i18n module (`@wxt-dev/i18n`)**, which parses `_locales/` at build time to generate typed helper functions with full IDE autocompletion and parameter validation.

```

│                                       WXT i18n Compilation Flow                                        │
├────────────────────────────────────────────────────────────────────────────────────────────────────────┤
│                                                                                                        │
│   ┌────────────────────────────────────────────────────────────┐                                       │
│   │ Locale Source Files (public/_locales/)                     │                                       │
│   │  ├── en/messages.json (Base Locale SSOT)                   │                                       │
│   │  ├── es/messages.json                                      │                                       │
│   │  ├── ja/messages.json                                      │                                       │

│   │  export type MessageKey = 'extName' | 'refineBtn' | ...    │                                       │

```

## 3. Manifest Localization (`wxt.config.ts`)

To allow browser stores and extension management screens (`chrome://extensions`) to localize the extension title and description dynamically based on the user's OS language:

```typescript
// wxt-extension/wxt.config.ts
export default defineConfig({
  manifest: {
    name: '__MSG_extName__',
    description: '__MSG_extDesc__',
    default_locale: 'en'
  }
});
```

## 4. React 19 Usage & Hook Integration

Inside UI components (Side Panel, Popup, Injected Overlays), translations are consumed via typed calls:

```tsx
// wxt-extension/src/components/injections/RefinerBadge.tsx
import React from 'react';
import { i18n } from 'wxt/i18n';

interface RefinerBadgeProps {
  platform: string;
  onRefine: () => void;
}

export const RefinerBadge: React.FC<RefinerBadgeProps> = ({ platform, onRefine }) => {
  return (
    <button 
      onClick={onRefine} 
      className="allie-badge-btn"
      title={i18n.t('refineButtonLabel', [platform])}
    >
      <span className="badge-text">{i18n.t('refineButtonLabel', [platform])}</span>
    </button>
  );
};
```

## 5. Bidirectional (RTL) Language Support

For right-to-left languages (e.g. Arabic, Hebrew):
- The Side Panel and Injected UI check `chrome.i18n.getMessage('@@bidi_dir')` on mount.
- If `'rtl'`, the root container applies `dir="rtl"` and swaps margin/padding coordinates to maintain clean visual balance.
