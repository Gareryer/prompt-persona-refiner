# 17 - Internationalization (i18n) & Localization Architecture

> **Target Layer**: Multi-Language Localization, RTL Bi-Directionality & Validation Toolchain  
> **Tooling**: `@wxt-dev/i18n` / Chrome WebExtension `_locales`  
> **Supported Locales**: English (`en` - SSOT), Spanish (`es`), Japanese (`ja`), Simplified Chinese (`zh_CN`), German (`de`), French (`fr`)  
> **Classification**: Localization & Internationalization Specification

## 1. Overview & WXT i18n Architecture

Standard WebExtension localization requires querying raw string keys via `chrome.i18n.getMessage('key')`, which provides zero compile-time type safety, no placeholder verification, and fails silently if a key is mistyped.

**Allie Persona & Prompt Refiner** leverages **WXT's type-safe i18n module (`@wxt-dev/i18n`)**, which parses `public/_locales/` at build time to generate typed helper functions with full IDE autocompletion and parameter validation.

```

│                                       WXT i18n Compilation Flow                                        │
├────────────────────────────────────────────────────────────────────────────────────────────────────────┤

│   │ Locale Source Files (public/_locales/)                     │                                       │
```

### 2.1. Key Naming Convention: `{component}_{action}_{context?}`

| Pattern | Message Key | Description | Example English Output |
| :--- | :--- | :--- | :--- |
| `{comp}_{action}` | `refine_button` | Main prompt refinement action | "Refine Prompt" |
| `{comp}_{action}_{state}` | `refine_button_loading` | Button state during stream | "Refining prompt..." |
| `{comp}_{item}_{action}` | `persona_card_delete` | Delete button tooltip | "Delete this persona" |
| `{comp}_{action}_{ctx}` | `persona_delete_confirm` | Modal dialog prompt with name | "Delete \"$PERSONA_NAME$\"?" |
| `settings_{item}_{prop}` | `settings_apiKey_label` | Input field label | "Provider API Key" |
| `error_{code}` | `error_rateLimited` | Notification toast | "Rate limit exceeded. Please wait." |

## 3. Locale Detection Priority

When mounting UI components in the sidepanel, options page, or Shadow DOM:

```
┌─────────────────────────────────────────────────────────┐
│ 1. User Preference in Storage (userSettings.language)   │
└───────────────────────────┬─────────────────────────────┘
                            │ if null / 'auto'
                            ▼
┌─────────────────────────────────────────────────────────┐
│ 2. Chrome Extension UI Language (chrome.i18n.getUILanguage())
└───────────────────────────┬─────────────────────────────┘
                            │ if unsupported
                            ▼
┌─────────────────────────────────────────────────────────┐
│ 3. Browser Navigator Language (navigator.language)      │
└───────────────────────────┬─────────────────────────────┘
                            │ if unsupported
                            ▼
┌─────────────────────────────────────────────────────────┐
│ 4. Fallback Default ('en' - English)                    │
└─────────────────────────────────────────────────────────┘
```

## 4. React 19 Hook & RTL Bi-Directional Support

For Right-to-Left languages (Arabic, Hebrew, Persian, Urdu):
- The extension checks `chrome.i18n.getMessage('@@bidi_dir')` or language prefix.
- The `RTLProvider` attaches `dir="rtl"` to the root container.
- Horizontal navigation icons (chevrons, back arrows) are inverted.

### 4.1. React Hook (`useI18n`)
```typescript
// wxt-extension/src/hooks/use-i18n.ts
import { useCallback } from 'react';
import { i18n } from 'wxt/i18n';

export function useI18n() {
  const t = useCallback((key: any, substitutions?: string | string[]): string => {
    return i18n.t(key, substitutions as any);
  }, []);

  const locale = chrome.i18n.getUILanguage();
  const isRTL = chrome.i18n.getMessage('@@bidi_dir') === 'rtl' ||
    ['ar', 'he', 'fa', 'ur'].some(lang => locale.startsWith(lang));

  return { t, locale, isRTL };
}
```

### 4.2. RTL Provider Component
```tsx
// wxt-extension/src/components/shared/RTLProvider.tsx
import React from 'react';
import { useI18n } from '@/hooks/use-i18n';

export function RTLProvider({ children }: { children: React.ReactNode }) {
  const { isRTL } = useI18n();

  return (
    <div dir={isRTL ? 'rtl' : 'ltr'} className="w-full h-full">
      {children}
    </div>
  );
}
```

## 5. Automated Translation Validation Script (`scripts/validate-i18n.ts`)

To ensure zero missing translation keys or mismatched placeholder counts before store deployment, a validation script runs during CI:

```typescript
// wxt-extension/scripts/validate-i18n.ts
import fs from 'node:fs';
import path from 'node:path';

const LOCALES_DIR = path.resolve(__dirname, '../public/_locales');
const BASE_LOCALE = 'en';

function validateTranslations() {
  const baseFilePath = path.join(LOCALES_DIR, BASE_LOCALE, 'messages.json');
  const baseMessages = JSON.parse(fs.readFileSync(baseFilePath, 'utf-8'));
  const baseKeys = Object.keys(baseMessages);

  const targetLocales = fs.readdirSync(LOCALES_DIR).filter(f => f !== BASE_LOCALE);
  let hasErrors = false;

  for (const locale of targetLocales) {
    const localePath = path.join(LOCALES_DIR, locale, 'messages.json');
    if (!fs.existsSync(localePath)) continue;

    const localeMessages = JSON.parse(fs.readFileSync(localePath, 'utf-8'));
    const localeKeys = Object.keys(localeMessages);

    // 1. Missing keys in target locale
    const missing = baseKeys.filter(k => !localeKeys.includes(k));
    if (missing.length > 0) {
      console.error(`❌ [${locale}] Missing ${missing.length} translation keys:`, missing);
      hasErrors = true;
    }

    // 2. Extra orphaned keys in target locale
    const extra = localeKeys.filter(k => !baseKeys.includes(k));
    if (extra.length > 0) {
      console.warn(`⚠️ [${locale}] Contains ${extra.length} orphaned keys:`, extra);
    }

    // 3. Placeholder integrity check
    for (const key of baseKeys) {
      if (!localeMessages[key]) continue;
      const basePlaceholders = Object.keys(baseMessages[key].placeholders || {});
      const localePlaceholders = Object.keys(localeMessages[key].placeholders || {});

      const missingHolders = basePlaceholders.filter(p => !localePlaceholders.includes(p));
      if (missingHolders.length > 0) {
        console.error(`❌ [${locale}] Key "${key}" missing placeholders:`, missingHolders);
        hasErrors = true;
      }
    }
  }

  if (hasErrors) {
    console.error('Translation validation failed.');
    process.exit(1);
  } else {
    console.log('✅ All translations validated successfully.');
  }
}

validateTranslations();
```

## 6. Pseudo-Localization & Visual Stress Testing

To verify UI robustness against text expansion (e.g. German text expanding up to 35% longer than English):
- During development, `VITE_PSEUDO_LOCALIZE=true` wraps string outputs with brackets and accents:
  > *"Refine Prompt"* $\rightarrow$ `"[!!! Ŕéƒîñé Ƥřömpţ !!!]"`
- Ensures buttons, modal headers, and Shadow DOM pills never suffer text clipping or unexpected layout shifts.
